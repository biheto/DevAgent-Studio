# 任务执行与历史记录改进

## 本次解决的问题

- 原来的三个任务流接口先同步执行整张图，再回放事件；等待模型或工具时，异步请求处理也被阻塞。现在使用后台线程执行同步图，提交到数据库的事件立即进入该请求独立的有界队列，再通过 SSE 发给浏览器。可视工作流和协作节点都支持执行中的事件推送；PR 审查目前提供任务开始、审查结果和任务结束事件，不提供模型逐 token 输出。
- 历史列表原来一次加载全部任务及其报告全文。现在由服务端搜索和分页，只返回摘要字段，并使用时间与插入顺序稳定排序。历史面板提供加载、空结果、请求失败重试和移动端翻页状态。
- 报告只能在界面查看。现在可以从报告中心或历史报告预览下载保存的 Markdown 原文，保留中文和代码块。

## 使用方式

1. 在任务工作台运行任务，执行动态随已提交事件更新；单个节点完成不会把整项任务误标为完成。
2. 在历史任务中搜索任务目标、项目路径或任务 ID，选择执行状态，使用列表底部的上一页、下一页浏览。
3. 选择已有报告的任务，点击“导出 Markdown”。尚无报告或当前任务执行中时禁用导出。

正在执行时暂时禁止切换历史任务，避免两项任务的动态和报告混在一起。历史详情的异步加载会忽略过期响应。

## 接口

`GET /api/v1/tasks?q=关键词&status=failed&limit=20&offset=0`

- `q`：最长 200 字符，匹配目标、路径、ID；`%`、`_` 和反斜杠按普通文本匹配。
- `status`：可选，精确匹配状态；未知状态返回空列表。
- `limit`：默认 20，范围 1–100；`offset`：非负整数。
- 响应：`{ tasks, total, limit, offset }`。列表不再返回 `final_report`，改为 `has_report`；需要报告内容的客户端使用任务详情或报告接口。原本依赖一次返回全部任务的客户端需要翻页。

`GET /api/v1/tasks/{task_id}/report/download`

返回 UTF-8 Markdown 附件；任务不存在返回 404，尚无报告返回 409。保留原有 JSON 报告接口。

三个现有 POST 流接口保持路径和 `task_result` / `complete` 协议。增加 15 秒心跳、禁止代理缓冲、事件去重；共享部署身份会传入工作线程。前端共用增量解析器，支持分包 UTF-8、LF/CRLF/CR、多行 data 与心跳注释；收到完成标记前断线会提示到历史任务检查进度。

## 执行边界

浏览器断开不会取消任务；只要服务进程存活，任务会继续执行并持久化。可视工作流、多智能体协作、项目入门和架构治理支持持久化检查点恢复；失败且存在检查点时，任务详情和历史页提供“从检查点继续”。待审核任务必须通过审核接口继续，草稿不能作为正式报告导出。

重启服务不会自动调度遗留任务；进程意外退出后可在执行租约过期后调用恢复接口。旧任务没有检查点时不能自动恢复。不自动重发 POST，也不自动重新执行任务，避免重复调用有副作用的工具。协作恢复、审核和剩余能力边界见 [Agent 执行说明](AGENT_EXECUTION.md)。
