# 有预算的 Agent 执行与候选修复

## 使用

1. 在任务工作台选择“多智能体”，或选择项目入门、架构治理。
2. 展开“协作与费用”。可以选择并行执行独立 Agent、开启项目副本自动修复，以及设置费用和 token 上限。
3. 运行前预估自动更新。金额使用 USD；填写的输入/输出单价适用于本任务所有模型，留空则读取各模型环境配置。
4. 执行期间，任务详情显示供应商报告 token、计入预算的用量和估算费用。预算不足时保存检查点，界面提供“保存预算并继续”。
5. 开启修复时，在副本中生成精确修改，运行验证，将结果交给 Planner 重新规划，再复查。审核通过后，查看差异，点击“应用修复到原项目”。

这些设置适用于协作图及复用该图的入门、治理场景。可视工作流、单独工具、聊天、PR 审查和 RAG embedding 的费用暂不进入此任务账本。

## 预算怎么算

运行前估算不调用模型，也不扫描项目全文。它按文件上限、预计 Agent 调用、输出上限和最大修复轮次计算粗估；目标可能选择更少的 Agent，实际提示词和重试也可能不同，所以这不是报价。

每次付费模型调用前，任务账本在 SQLite 事务中预留输入与输出额度。输入使用 UTF-8 字节数加消息余量的保守估算；输出按每次调用上限预留，并把该上限传给模型客户端，同时关闭客户端自动重试。并行分支共享同一账本，不能分别花掉同一份剩余额度。

收到完整的输入/输出 token 后，用供应商报告值替换预留，再按该次调用保存的配置单价计算费用。超时、缺少完整用量、进程崩溃留下的预留不会自动归零，分别显示为“待确认”或“在途”，继续占用预算。没有 API key 的规则 fallback 不计作付费调用。

达到上限或剩余额度不足以预留下一次调用时，任务进入 `budget_paused`。在途调用可完成结算；提高预算不会重置已用额度。金额预算启用而模型单价缺失时，也会暂停。显式配置 0 才表示免费。补充单价时，可以为此前缺价的调用补算费用；已经有单价的历史调用保留原计价依据。

费用不包括供应商缓存折扣、税费、工具收费及其他账单项目。配置单价错误、供应商报告超出预留等情况，可能导致最终账单超过此处估计；系统控制的是后续调用准入，不能撤回已经发生的费用。实际支付金额以供应商账单为准。

默认只设置 100000 token 上限，不假设用户的金额预算。单次输出默认 2048 token，可通过 API 调整到 128–16384。账本与检查点同处 `DEV_AGENT_CHECKPOINT_DB` 对应的 journal 数据库，重启后仍保留。

模型价格沿用环境变量，例如：

```env
# 填入你实际使用渠道的单价，不提供过时的内置价格。
DEV_AGENT_LLM_PRICE_GPT_4O_MINI_INPUT_PER_1M=
DEV_AGENT_LLM_PRICE_GPT_4O_MINI_OUTPUT_PER_1M=
# 可单独指定修复模型；不指定则使用默认模型。
DEV_AGENT_LLM_MODEL_REPAIRER=
```

## 修复边界

- 最多 3 轮，每轮最多 8 处精确替换；原文必须唯一匹配。只允许修改证据对应的已有源文件，不接受模型生成的命令，不生成任意新文件。
- 项目副本最多 3000 个文件 / 20 MB；排除隐藏文件、凭证文件、依赖目录、Git 和生成物，不跟随符号链接或目录 junction。保留原文件换行符。
- 模型不能修改测试文件、conftest、测试配置来掩盖失败。代码变化本身仍需人审，不能把验证通过当作逻辑正确的保证。
- `python_compile` 仅编译 Python 语法，不执行代码，也不验证业务行为。没有 Python 文件时不会声称验证通过。
- `pytest` 使用服务端 Python 环境运行真实项目测试，最长等待 60 秒；不自动安装依赖，禁用自动加载 pytest 插件，传入精简环境变量。缺少依赖、没有测试或测试失败都不是成功。**它在本机运行项目代码，不是安全沙箱；只对受信任项目显式选择此项。**
- 未配置模型或模型没有给出有效修改时，展示未修复原因并等待审核，不伪造补丁。
- 到达轮次上限后停止迭代，保留验证输出、修复历史和剩余风险。只能应用最后一个已通过验证并完成审核的候选。
- 应用前检查候选文件哈希与原文件基线；原文件有新修改、候选被篡改时返回冲突，不覆盖。应用按文件原子替换，可幂等重试；多文件应用不是跨文件事务，进程中断时可能只完成其中部分文件。
- 副本保留在 `DEV_AGENT_REPAIR_DIR`，默认 `data/repair_runs`，用于后续审核；本轮没有自动清理策略，目录不进入 Git，也不作为静态资源公开。

## API

`POST /api/v1/tasks/collaborate` 和入门/治理场景请求增加：

```json
{
  "goal": "审查项目并修复可定位的问题",
  "project_path": "D:/projects/example",
  "parallel_workers": true,
  "repair_options": {"enabled": true, "max_rounds": 2, "validation": "pytest"},
  "budget": {
    "max_cost_usd": 1,
    "max_tokens": 100000,
    "output_tokens_per_call": 2048,
    "input_price_per_1m": null,
    "output_price_per_1m": null
  }
}
```

示例中的 1 USD 是任务上限，不是推荐模型价格。单价为 null 时使用各模型配置，配置缺失则不能开始受金额预算保护的调用。

| 接口 | 用途 |
| --- | --- |
| POST `/api/v1/tasks/estimate` | 接收任务选项，返回估算 token、费用、分步估算依据；不调用模型。 |
| GET `/api/v1/tasks/{id}/budget` | 实时账本、已报告用量、在途及不确定调用、预算配置。 |
| PUT `/api/v1/tasks/{id}/budget` | 更新暂停任务的完整 budget 对象；保留既有消耗，执行租约期间拒绝更新。 |
| POST `/api/v1/tasks/{id}/recover` | 从预算暂停或失败检查点继续；待审核任务仍必须通过审核接口。 |
| POST `/api/v1/tasks/{id}/repair/apply` | 显式应用已验证、已审批且报告阶段完成的候选，返回受影响文件。 |

任务结果增加 `budget_usage`、`parallel_workers`、`repair_result`、`repair_history`。预算修改和应用修复需要 editor/admin 权限。终态任务不允许再次 recover；新分析应创建新任务。
